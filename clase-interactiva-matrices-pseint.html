02 · Fundamentación conceptual

¿Qué es un arreglo?

En el tratamiento clásico de estructuras de datos, Luis Joyanes Aguilar presenta los arrays o arreglos como conjuntos finitos y ordenados de elementos homogéneos. Sus componentes pertenecen a un mismo tipo de dato y se localizan mediante una posición o índice.

Un arreglo permite agrupar datos relacionados bajo un identificador, en lugar de manejar una variable independiente para cada elemento.

Finito

Tiene una cantidad determinada de elementos.

Ordenado

Sus elementos ocupan posiciones identificables por índices.

Homogéneo

Sus elementos comparten tipo de dato: enteros, reales, etc.

Precisión: “arreglo bidimensional” describe una estructura organizada en filas y columnas. “Matriz” es también una denominación didáctica habitual. Aquí se estudia almacenamiento y acceso a datos, no operaciones de álgebra matricial.

Referencia central: Joyanes Aguilar, Fundamentos de programación: algoritmos, estructura de datos y objetos, 5.ª edición (2020), sección sobre arrays y estructuras de datos.

03 · Clasificación

Una dimensión y dos dimensiones

Arreglo unidimensional

Secuencia de elementos; se accede con un índice.

Dimension Precios[4]
Precios[1]
Precios[2]

Ejemplo: precios unitarios.

Arreglo bidimensional

Elementos en filas y columnas; se accede con dos índices.

Dimension Compras[3,4]
Compras[1,1]
Compras[2,3]

Ejemplo: cantidades por cliente y producto.

Cliente / Producto1 · Teclado2 · Mouse3 · Monitor4 · USB
Cliente 11201
Cliente 20112
Cliente 32103
Compras[3,4] representa 3 filas y 4 columnas: 12 posiciones. Las filas identifican clientes y las columnas productos.

05 · Índices

¿Qué dato representa cada posición?

ExpresiónInterpretación
Compras[1,1]Cliente 1 compró 1 teclado.
Compras[1,2]Cliente 1 compró 2 mouse.
Compras[2,3]Cliente 2 compró 1 monitor.
Compras[3,4]Cliente 3 compró 3 memorias USB.
Comprueba: Compras[2,4] significa que el cliente 2 adquirió 2 memorias USB. Los ejemplos asumen índices desde 1; verifica el perfil de PSeInt.
06 · Implementación

Declarar, cargar y recorrer en PSeInt

Declaración

Definir Compras Como Entero
Dimension Compras[3,4]

Lectura de datos

Para i <- 1 Hasta 3 Hacer
    Escribir "Cliente ", i
    Para j <- 1 Hasta 4 Hacer
        Escribir "Cantidad del producto ", j
        Leer Compras[i,j]
    FinPara
FinPara

Mostrar el contenido

Para i <- 1 Hasta 3 Hacer
    Para j <- 1 Hasta 4 Hacer
        Escribir Sin Saltar Compras[i,j], "  "
    FinPara
    Escribir ""
FinPara
El ciclo externo controla filas y el interno columnas. El recorrido completo visita 3 × 4 = 12 elementos. Para una matriz de m filas y n columnas, se visitan m × n elementos.
07 · Caso aplicado

Sistema de facturación

La matriz almacena cantidades y un vector almacena precios unitarios. Se relacionan mediante el índice del producto.

ProductoPrecio
Teclado$45.000
Mouse$30.000
Monitor$650.000
Memoria USB$25.000
Subtotal = cantidad comprada × precio unitario

FACTURA · CLIENTE 1

ProductoCantidadSubtotal
Teclado1$45.000
Mouse2$60.000
Monitor0$0
USB1$25.000
Total cliente 1$130.000
TotalCliente <- 0
Para j <- 1 Hasta 4 Hacer
    Subtotal <- Compras[1,j] * Precios[j]
    TotalCliente <- TotalCliente + Subtotal
FinPara
Escribir "Total factura: ", TotalCliente

El acumulador del cliente se inicializa en cero para cada factura. El total general se inicializa una sola vez antes de procesar todos los clientes.

08 · Programa integrador

Algoritmo completo en PSeInt

Algoritmo FacturacionTienda
    Definir Compras Como Entero
    Definir Precios Como Real
    Definir i, j Como Entero
    Definir Subtotal, TotalCliente Como Real
    Definir TotalGeneral Como Real

    Dimension Compras[3,4]
    Dimension Precios[4]

    Precios[1] <- 45000
    Precios[2] <- 30000
    Precios[3] <- 650000
    Precios[4] <- 25000

    Para i <- 1 Hasta 3 Hacer
        Escribir "CLIENTE ", i
        Para j <- 1 Hasta 4 Hacer
            Escribir "Cantidad del producto ", j
            Leer Compras[i,j]
        FinPara
    FinPara

    TotalGeneral <- 0
    Para i <- 1 Hasta 3 Hacer
        TotalCliente <- 0
        Escribir "FACTURA DEL CLIENTE ", i
        Para j <- 1 Hasta 4 Hacer
            Subtotal <- Compras[i,j] * Precios[j]
            TotalCliente <- TotalCliente + Subtotal
            Escribir "Producto ", j, ": ", Subtotal
        FinPara
        Escribir "Total cliente: ", TotalCliente
        TotalGeneral <- TotalGeneral + TotalCliente
    FinPara
    Escribir "TOTAL GENERAL: ", TotalGeneral
FinAlgoritmo
Verificación: cliente 1 = $130.000; cliente 2 = $730.000; cliente 3 = $195.000; total general = $1.055.000.
09 · Taller

Transferencia del aprendizaje

Extiende el sistema para cinco clientes y seis productos.

  1. Define una matriz de 5 × 6.
  2. Define un vector de seis precios.
  3. Registra las cantidades compradas por cada cliente.
  4. Calcula subtotal por producto y total por cliente.
  5. Calcula el total general de ventas.
  6. Determina el cliente con la compra de mayor valor.
  7. Determina el producto que generó mayores ingresos.
  8. Explica por qué los precios se representan con un vector y las cantidades con una matriz.
Reto: si agregas dos clientes, ¿qué dimensión cambia? Si agregas un producto, ¿qué dimensión y qué vector cambian?
